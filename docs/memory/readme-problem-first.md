# README 先解释解决的问题（2026-11-17）

- **触发场景 / 适用范围**：修改本项目 README 的定位、介绍、结构或使用示例时。
- **问题模式**：用户先指出 README 没有说清楚解决什么问题，随后纠正了将定位偏向 Bug 排查与任务收尾的介绍。better-code 的主线应是帮助 AI 写出更好的代码，排障只是配套能力；堆叠工程术语、技能目录和配图也不能替代用途说明。
- **可执行规则**：
  1. 以“帮助 AI 写出更好的代码”为核心定位，具体解释模块边界、职责归属、类型与错误处理、能力复用、加载性能和验证。
  2. 开头说明产品形态、目标用户和代码质量问题，首次使用以功能开发或重构为例；不把项目写成主要用于修 Bug 的工具。
  3. 以“遇到的情况 → 调用方式 → 可观察的产物”组织说明；首次使用不要求走完整技能链，排障和归档放在辅助流程中。
  4. 明确区分技能要求、真实验证结果和未测试的预期行为；避免“彻底终结”“保证零缺陷”等无依据承诺。
  5. 当用户要求先调研、之后再参考时，先提交有来源的建议；用户明确授权重写后继续实施，无需重复询问。
- **检查方式**：读完开头应能说明代码会在哪些方面变好；第一条任务示例用于写功能或重构；复杂细节通过链接继续阅读。
- **参考**：[Markdown 与 README 调研](../research/readme-writing.md)、[配图风格约定](readme-image-style.md)。
