## 实际提交的提示词

```text
为开源开发工具的 GitHub README 制作一张横版 16:9 工程对比插画。
输入参考图是用户已认可的同系列工作流总览。只继承它的米白背景、深炭色线条、低饱和青绿色、简洁二维图形、字形和宽松留白，不复制其中的四阶段布局和文字。

视觉规范：
米白背景 #F7F5F0，深炭色文字与线条 #24272B。
左列用少量陶土橙 #C97C5D 表示问题，右列用少量青绿 #287D75 表示改进。
统一线宽，简洁几何图形，轻微柔和的纸感，清晰的印刷体中文，英文标题使用参考图的粗体字形。
色号和颜色名称仅是绘制指导，不能出现在图片中。
目标展示宽度约 900 像素，所有标签需要足够大；不使用发光、霓虹、玻璃面板、金属质感、粒子、密集背景网格或复杂阴影。

图的目标：比较三种工程问题与对应的改进方法。

布局：
左右两列，使用细分隔线与完全对齐的三行，左右信息量相当。
左列标题“缺少工程约束”，右列标题“better-code”。
标题区简洁，内容占据主体。每个格子只保留一个简洁图形和一条短标签。
每一行两边图形处于相同高度，形成一眼可比较的对应关系。各格之间留白，不堆叠多层边框。

第一行：
左边画四个没有明确边界、相互缠绕的小模块，标签“职责混杂”。
右边画三个边界清晰、接口相接的模块，标签“模块边界”。

第二行：
左边画一个只有问号和重复回转箭头的小循环，标签“猜测修补”。
右边画放大镜检查一条简化证据记录，再指向修复标记，标签“运行时证据”。

第三行：
左边画一份草稿被直接抛向终点，标签“改完就停”。
右边画检查清单与归档盒，标签“验证与归档”。

除上述两列标题及六条标签，不出现其他文字。
不绘制真实代码、目录树、日志行、状态机或虚构的效率百分比。
不将左边夸张成灾难画面，依靠对应关系说明差别。
不要添加额外的总标题、说明段落、底部横条、步骤编号或水印。
```
