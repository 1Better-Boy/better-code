# 结构化工程经验记忆（索引目录 + 按需加载）

将真实踩坑、用户纠正与工程特有约束沉淀为**结构化分类索引 + 独立按需加载条目**，避免把所有内容平铺堆进单个大文件，也避免每次会话全量读取无关正文消耗上下文。

## 1. 记忆库的三层结构设计（拒绝平铺堆砌）

先查看目标工程说明（`AGENTS.md` / `CLAUDE.md`），若工程已约定记忆目录（如 `notes/lessons/`）则严格沿用其路径；未约定时默认使用 `docs/memory/`，并按以下结构组织：

```text
docs/memory/
├── index.md                         # 【主入口】结构化分类目录（仅列分类、主题链接与一句话触发场景，绝不放规则正文）
├── <category>/                      # 【可选分类子目录】条目较多（如 ≥8 条）或领域清晰时按领域分目录（architecture / testing / workflow / pitfalls）
│   └── <kebab-case-slug>.md         # 【独立条目】单一主题的问题模式、可执行规则与适用范围
└── <kebab-case-slug>.md             # 【独立条目】条目较少或工程既有约定为单层目录时，直接放在记忆根目录下，由 index.md 按分类标题组织
```

- **主索引文件（`index.md`）铁律**：只作为**结构化路由表**，按领域分章节（如 `## 架构与模块边界`、`## 编码与测试规范`、`## 协作与工作流边界`），每条只写 `- [<经验主题>](<相对路径>.md) — <适用模块/触发场景一句话摘要>`，**严禁把长篇经过或规则正文塞进 `index.md`**。
- **独立条目文件（`<slug>.md`）铁律**：每个文件只聚焦**一个独立主题**，包含发生条件、问题模式与可观察的执行判据；相关条目之间通过 Markdown 相对链接（如 `[文件名](other-slug.md)`）互相引用，绝不跨文件复制大段相同规则。

## 2. 按需加载工作流（三级渐进读取）

会话开始或处理任务读取工程记忆时，严格执行**“先读索引 → 按任务筛选 → 仅读命中条目”**：

1. **第一步：只读主索引 `index.md`**
   - 读取工程约定的索引文件（默认 `docs/memory/index.md`），**严禁一上来用通配符全量读取记忆目录下的所有 `.md` 正文**。
   - 若索引不存在：对于只读查询，直接说明尚未建立工程记忆，**绝不为只读请求自动创建目录或空文件**；对于普通研发任务，直接继续处理任务即可。
2. **第二步：按当前任务精准匹配条目**
   - 根据当前任务涉及的**模块路径、动作类型（排查/规划/编码/测试/提交）或报错关键词**，从 `index.md` 的分类与一句话摘要中挑出相关的 1~3 个条目。
   - 索引未命中但怀疑存在历史记录时，先用 `Grep` 搜索关键词定位文件名，再读取命中的文件。
3. **第三步：按需读取命中正文并核实当前有效性**
   - 只读取命中的条目正文；若正文中有相对链接指向强关联的前置规则，再沿链接补读。
   - **以当前代码事实为准**：将历史条目用于指导当前实现前，先核实条目引用的文件路径、函数名、配置字段或命令是否仍然存在；若代码已重构演进，明确说明差异，不盲目套用过期事实。

## 3. 结构化记录与更新流程（防重复平铺）

当用户明确要求记住，或**用户在对话中纠正了你的错误做法**时，按以下步骤沉淀经验：

1. **先读索引、合并同类（严禁平铺新建重复文件）**
   - 先读 `index.md` 并搜索同类主题。若已有条目覆盖该领域（如已有 `report-each-failure.md` 讲失败报告规则），**必须先读取该条目原文并在原文件内增量更新/精细化规则，保留原有仍然有效的要求**，绝不因为换了个说法就新建第二个近义文件。
2. **提炼可执行规则与适用边界**
   - 区分**真实发生的错误/用户明确纠正**与**未经采纳的推测**；把“下次注意/要小心”转化为具体动作、命令与可观察判据。
   - **锁死适用范围**：一次任务的临时授权或特定场景限制（如“当用户明确要求只读排查时，不修改文件”），必须写清触发前提，绝不夸大成“任何任务都不准改文件”的全局死规矩。
3. **写入条目并维护 `index.md` 分类结构**
   - **首次初始化**：若工程尚无记忆目录，仅创建最小 `index.md` 和本次条目文件，不预建空的分类文件夹，也不向 Agent 私有全局目录复制正文副本。
   - **增量更新或新建**：新建主题时，若有明显差异化前置规则已在其他条目完整写明，仅在新条目写本次差异并用相对链接 `[已有条目](existing.md)` 指向它。随后在 `index.md` 对应分类标题下补一行相对链接入口（无分类时按主题归入合适分类标题），确保每个条目在 `index.md` 中**有且仅有一个入口**。
4. **验证链接与简洁交付**
   - 确认新/改条目的相对路径真实存在、未覆盖无关文件，向用户简短汇报新增或更新的规则要点及可点击的文件路径。

## 4. 标准模板（工程无既有格式时采用）

### 主索引模板（`docs/memory/index.md`）

```markdown
# 工程经验索引

会话开始仅读取本索引，按当前任务所属分类与触发场景按需加载对应条目，不全量加载正文。

## 协作与工作流边界
- [<经验主题>](<kebab-case-slug>.md) — <何时触发/适用什么场景的一句话说明>

## 架构、编码与测试
- [<经验主题>](<kebab-case-slug>.md) — <何时触发/适用什么场景的一句话说明>
```

### 独立条目模板（`docs/memory/<kebab-case-slug>.md`）

```markdown
# <经验主题>（YYYY-MM-DD）

- **触发场景 / 适用范围**：<在什么模块、什么请求前提或什么操作下适用；明确边界>
- **问题模式**：<真实失败或用户纠正的简短经过，保留理解规则所需的条件与根因>
- **可执行规则**：
  1. <具体动作、检查命令或代码判据>
  2. <需要关联其他已存在规则时，使用相对链接引用：[关联主题](related-slug.md)>
```
